# Phase 001, Deliverable 20: Comparative Report, v0.1.3 vs Bitcoin Core v28.1 vs NOVA Production

Project: NOVA SHA-X, Research Phase 001, Wave 4.
Sources: the original form from Phase 001 deliverables 1 to 13; the modern Core form from research/bitcoin_core/ (CORE_SOURCE_AUDIT.md, MINING_CALL_GRAPH.md, POW_DIFFICULTY_SOURCE.md), all at the pinned v28.1 tree, commit 32efe850438ef22e2de39e562af557872a402c31; the NOVA form from research/bitcoin_reverse_engineering/NOVA_REPOSITORY_AUDIT.md, verified against the production code line by line. Status column meanings: PRESERVED (same semantics in all three), EVOLVED (same function, materially better modern form), REPLACED (the original mechanism no longer exists in that role), GAP (a function one side has and another lacks).

## 2. Reading the table: three conclusions the evidence supports

1. **The consensus-critical mathematics is the most conservative layer.** SetCompact's edge semantics were the only place the 2009 code's behaviour genuinely differed from the modern rule, and even there the difference is confined to encodings the chain never carries, fenced in 0.1.3's own time by the AcceptBlock nBits equality gate. The hash function, the header layout, the merkle rule and the retarget arithmetic (including the 2015-interval span quirk, identical in both eras) are PRESERVED in substance across all three codebases.
2. **Everything about work management was replaced.** The 0.1.3 miner is a loop inside a GUI; Core externalized mining entirely and offers only a regtest-grade internal loop; NOVA rebuilt the work layer (counted search, checkpoints, template identity, evidence counting) because neither ancestor provides it. The EXP-030 Phase B gap analysis (3 missing components: Work Lease Manager, Distributed Agent Coordinator, Candidate Queue) is the same conclusion from the other direction.
3. **Midstate is the one mining-specific idea NOVA has that neither Bitcoin codebase ever adopted**, for a structural reason: Core's hash API serves all hashing, not mining, and generality forbids the mining-shaped interface. The genesis engine's failure to reuse state was an oversight; Core's is an architecture. NOVA's kernels exist in the space both left empty.

## 3. Limitations

- The Core column describes the pinned v28.1 source, not master (the audit rule: master HEAD at retrieval was not analysed).
- The NOVA column describes production as audited; research-tier code (EXP-032 tiers, EXP-035 prototype) appears only where the row says so.
- Historical judgements about 0.1.3 are source judgements; nothing here claims what any historical binary did at runtime beyond what the source and the genesis anchors prove.
