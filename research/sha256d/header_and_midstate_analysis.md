# Header Layout, Midstate, and the Precomputation Ceiling (Stage 2)

This is the canonical word-level derivation for this programme.
One indexing is used throughout: message words are numbered
within their own 64-byte block, W0..W63, each word big-endian.

## The 80-byte header, byte by byte

| Bytes | Field | Block | Word(s) |
|---|---|---|---|
| 0..3 | version | inner block 1 | W0 |
| 4..35 | previous block hash | inner block 1 | W1..W8 |
| 36..63 | merkle root, first 28 bytes | inner block 1 | W9..W15 |
| 64..67 | merkle root, last 4 bytes | inner block 2 | W0 |
| 68..71 | timestamp (nTime) | inner block 2 | W1 |
| 72..75 | nBits | inner block 2 | W2 |
| 76..79 | nonce, little-endian in the header | inner block 2 | W3 |

The nonce's header encoding is little-endian (the 4 bytes are
the nonce integer in little-endian order); the schedule reads
the word big-endian, so W3 of block 2 is the byte-reversed
nonce. Implementations that patch bytes 76..79 with the
little-endian nonce and then load W3 big-endian are doing
exactly this, and the lab's genesis checks pin it down
(nonce 2083236893 reproduces the known hash on every path).

Inner block 2 padding words: W4 = 0x80000000, W5..W13 = 0,
W14 = 0, W15 = 640 (the bit length). All constants.
Outer block words: W0..W7 are the inner digest words,
W8 = 0x80000000, W9..W14 = 0, W15 = 256. The padding words are
constants; the digest words change with every candidate.

## Where the nonce first bites

In block 2, rounds 0, 1, 2 consume W0 (merkle tail), W1
(timestamp), W2 (nBits). None of them involves the nonce.
Round 3 consumes W3, the nonce word: that is the first round
whose T1 depends on the nonce.

Schedule words W16..W63 of block 2 are generated by the
recurrence from W0..W15:

    W[t] = sigma1(W[t-2]) + W[t-7] + sigma0(W[t-15]) + W[t-16]
    sigma0(x) = ROTR7(x) XOR ROTR18(x) XOR SHR3(x)
    sigma1(x) = ROTR17(x) XOR ROTR19(x) XOR SHR10(x)

W3 IS the nonce: a direct message word, consumed by round 3.
That is a different statement from which EXPANDED word
(t >= 16) first depends on it. Checking the recurrence inputs:

- W16 draws on W14, W9, W1, W0 (t-2, t-7, t-15, t-16):
  no W3, so W16 is nonce-independent.
- W17 draws on W15, W10, W2, W1: no W3, nonce-independent.
- W18 draws on W16, W11, W3, W2: the t-15 input is W3, the
  nonce word. W18 = sigma1(W16) + W11 + sigma0(W3) + W2 is
  therefore the FIRST expanded schedule word that carries
  nonce dependence.

(Correction, Stage 5 authorization 2026-11-14: an earlier
revision of this file said W19. That was an indexing error;
the recurrence gives W18, as shown above. The correction
concerns schedule-word indexing only: no round-based claim
in this file changes, and the 67/192 precomputation ceiling
below stands.) By the time W18 is consumed (round 18) the
state has depended on the nonce since round 3 anyway. The precise statement is about state, not schedule:
the block-2 state after rounds 0..2 is a function of
(midstate, merkle tail, timestamp, nBits) only. From round 3
onward, every state word is nonce-dependent through the round
feed-forward, so nothing later in block 2, and nothing in the
outer hash, can be precomputed across nonces.

Reconciliation with the intrinsics code: bal_sha_intrin.c packs
its per-template work in its own layout and snapshots the inner
state after round 1, noting the nonce is first consumed by
round 3. Both statements are consistent: its snapshot is taken
early because SHA256RNDS2 computes rounds in pairs (rounds
2 and 3 form the next pair, and round 3 needs the nonce), so
the last pair boundary before any nonce-dependent round is
after round 1. The canonical ceiling (state after round 2)
would need one unpaired scalar round or a repacked state
layout; that gap is hypothesis H-02's subject, and it is worth
exactly one round of block 2 per candidate.

## The precomputation ceiling, in rounds

Per candidate, total work is 192 compression rounds.

Reusable across all nonces of one fixed template:
- Inner block 1: 64 rounds, once per template. The production
  C backend already does this (the midstate).
- Inner block 2, rounds 0..2: 3 rounds, once per template.
  Not yet exploited by any lab path (OpenSSL's SHA256_Transform
  API takes whole blocks from a state, so the production path
  cannot split block 2 mid-way through its public API; the
  intrinsics path could, subject to the pairing limit above).

Ceiling: 67 of 192 rounds are template-invariant, about 34.9%.
Per-nonce work can never fall below the remaining 125 rounds
(61 of block 2 plus 64 of the outer hash) by precomputation
alone. Any claim of a larger saving is not precomputation; it
would have to be a different evaluation strategy for the same
rounds (parallel streams, wider SIMD, better scheduling), which
is where the rest of the registry aims.

The outer hash admits NO cross-candidate reuse beyond its
constant initial state and its constant padding words: its
input is the inner digest, which is nonce-dependent in full.

## Invariance classes: what a field change invalidates

- Nonce only: nothing precomputed is invalidated. The midstate
  and the block-2 prefix state (rounds 0..2) both survive.
- Timestamp change (timestamp rolling): block 1 and the
  midstate survive; block-2 W1 changes, so the prefix state
  must be recomputed (3 rounds). Cheap; see H-13.
- nBits change: same cost class as timestamp (W2, prefix state
  recomputed; happens only when the template target changes).
- Merkle root change (new extranonce, new transaction set):
  block 1 contains merkle bytes 0..27, so the midstate itself
  is invalidated, and block-2 W0 (the last 4 merkle bytes)
  changes too. Full re-precompute: 67 rounds per new template,
  still trivial against a nonce range.
- Previous hash or version change: block 1 invalidated, same
  as a merkle change.

Quantified reuse, production today: for a template mined over
N nonces, production pays 64 + 128N rounds instead of 192N.
At the live miner's roughly 4.2M-nonce spans, the midstate
saves about 33% of the naive round count, and the remaining
theoretical precomputation headroom (3 rounds in 125, about
2.4% of per-nonce work) is small, bounded, and known. The big
remaining lever is not more precomputation; it is evaluating
the 125 rounds faster (H-01, H-05, H-06) and wasting none of
them on stale work (Stage 7).
