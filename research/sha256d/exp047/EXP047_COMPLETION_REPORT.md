## 1. Why a corrected criterion

The original campaign's criterion S-C required
search_first_counted to return the span minimum hit,
identically on every backend. That invariant is false in
production by design: mining/cpu/bal_search.h partitions
the span per thread and bal_ctx_publish is
first-publisher-wins, so a multithreaded native search
returns the first genuine hit its thread partitions
publish, not the span minimum (EXP047_REPORT.md section
5.3, ESTABLISHED NEGATIVE, characterized over 1,242 calls
with zero wrong digests, zero false hits and zero false
misses). The original campaign stopped at its first case
under its failure rule, leaving the remaining search cases
and the whole Gate 3 set unexecuted. This completion
campaign executes that remainder under a criterion that
tests what production search actually promises: found-flag
correctness and hit genuineness. Minimum identity is
measured, not judged.

## 2. Corrected S-C criterion (predeclared)

For every search case in section 3 and every backend
(v512dual, v512, shani, avx2, c, cpu), the
search_first_counted surface passes if and only if:

- (a) Found-flag agreement: the call returns a hit if and
  only if the hashlib reference hit set for the span is
  non-empty. Agreement with the reference implies pairwise
  agreement across backends; both are checked and any
  disagreement is a campaign failure under section 4.
- (b) Genuineness: every returned nonce lies inside the
  span [start, start + count), its digest as returned
  equals cpu_digest(header, nonce) exactly, and the digest
  read little-endian is <= the case target (equality
  meets). A returned nonce failing any part is a false hit
  or a wrong digest, a campaign failure under section 4.
- (c) Minimum identity is a STATISTIC, never pass/fail:
  per backend, with its tuned thread count recorded, the
  campaign counts S-C calls whose returned nonce equals
  the reference span minimum, calls returning a different
  genuine hit, and the offset (returned nonce minus span
  minimum) for each non-minimum return.

The hit-set surfaces keep the original exact criterion:
batch_search (S-A) and the raw flagged pairs (S-B),
including the EXP-022 flags-library pairs on the v512 and
v512dual engines, must reproduce the reference hit set
exactly (set equality) on every case and backend, every
flagged pair's digest must equal cpu_digest, and
batch_search stats must show the pinned backend,
verification_failures 0 and no rescan on every call. Any
extra nonce is a false hit, any missing nonce a false
miss, any digest inequality a wrong digest: campaign
failures under section 4.

The two S_FIRST_BOUNDARY calls are executed as S-C calls
under this same criterion: found-flag agreement and
genuineness are judged; identity with the named nonce
(2^32 - 1 for the single-nonce span, the genesis nonce
2083236893 for the DIFF1 span) is recorded under (c). For
the single-nonce span identity is forced by the span
itself; for the DIFF1 span the reference hit set is
computed and identity is whatever the evidence shows.

## 4. Gate 3 set and failure rule (predeclared)

Gate 3 (input dimension), executed as campaign items, per
engine (all six) through batch_search unless noted; every
case must raise ValueError, uniformly across engines:

- G1 header 79 bytes; G2 header 81 bytes; G3 target 0;
  G4 target 2^256; G5 target -1; G6 start -1; G7 count 0;
  G8 count -5; G9 count 1,048,577 (MAX_BATCH + 1);
  G10 crossing span start 2^32 - 100, count 200;
  G11 start 2^32, count 1.
- G12 search_first_counted crossing span; G13
  search_first_counted target 0; G14 search_first_counted
  header 79 bytes.

Per native backend (five), at the library ABI the seam
wraps: G15 _x_batch_flagged over start 2^32 - 8, count 16
(crossing) must refuse (return None, no pairs); G16
_x_batch over the same span must refuse (return None).
Spans ending exactly at 2^32 are valid and are covered by
the search ladder (S_FULL-01) and the original batch
campaign, not here. Gate 3 verdict: PASS if and only if
every G1 to G14 case raises ValueError on every engine
and every G15/G16 refusal holds on every native backend;
any deviation is recorded as a defect with the exact case,
engine and observed behaviour.

Failure rule (whole campaign): any found-flag
disagreement, false hit, false miss, or wrong digest
stops the campaign at once; the full case (backend, case
id, header, start, count, target, nonce, expected and
actual) is recorded to
RAW_RESULTS/completion_mismatch.json, shrunk to a minimal
repro where the failure shape permits, and written up in
this report as a defect. Production code is not modified
by this campaign under any outcome. Campaigns run one at
a time; nothing here times anything for a result (no hash
rate is a campaign output). The live mining stack is
never touched, signalled, restarted or reconfigured; the
share census is read from evidence/mainnet-live.jsonl
before and after.

## 7. Limitations and unverified register

- CUDA: absent on this host, untested by this campaign,
  as by the original.
- Single host (AMD EPYC 9D25); thread counts auto-tune per
  engine construction and vary with contention (v512dual
  and v512 tuned 8 threads this run, 2 and 4 in earlier
  runs), so the minimum-identity rates in section 5.2 are
  host-and-load specific; the genuineness and found-flag
  results are not rate claims of any kind.
- T_SOLO produced zero reference hits in 8,388,608 nonces
  per backend, as expected at its density (about 0.098
  expected); what is verified at the solo density is
  empty-set agreement, not hit handling. Hit handling at
  densities 2^-24 and denser is verified with hits present
  (S_D24 produced one, S_D16 and denser many).
- Nothing in this campaign measures performance; no hash
  rate is reported as a result.

and document first-publisher-wins, or pay for a minimum

production search semantics. It supersedes the original
minimum-identity criterion (criterion S-C as first
predeclared), which remains an ESTABLISHED NEGATIVE: a
multithreaded native search returns the first genuine hit
its thread partitions publish (mining/cpu/bal_search.h,
bal_ctx_publish over bal_partition thread spans), not the
span minimum, and no minimum reduction will be paid for
in the production search context. The corrected-criterion
re-verification stands as recorded above (search VERIFIED
under the corrected criterion: found-flag agreement and
hit genuineness on every backend, with minimum identity
recorded as a statistic). A caller that needs the span
minimum uses batch_search enumeration (exact here and in
the batch campaign) or a single-threaded search, which
returns the minimum.
