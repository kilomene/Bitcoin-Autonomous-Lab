# Task 002: Blockchain Intelligence Engine

Status: implemented and tested on the Lab Regtest node. Evidence:
evidence/regtest/task002-evidence.json, generated by the test run.

## Components

- blockchain/store.py: SQLite storage (WAL mode). Tables: blocks,
  transactions, sync_status, chain_events. Reorg safety:
  invalidate_from(height) deletes block rows at and above the fork
  and returns their transactions to mempool tracking.
- blockchain/transactions.py: TxInspector. getrawtransaction,
  decoderawtransaction, getmempoolinfo, getrawmempool,
  getmempoolentry. Fees computed exactly (inputs minus outputs) and
  cross-checked against getmempoolentry. Unavailable transactions
  raise TxUnavailable with the node's reason: never fabricated.
- blockchain/analysis.py: BlockAnalyzer. Rebuilds the 80-byte header,
  recomputes the merkle root from the block's txids, rehashes the
  header and checks it against the nbits target, computes difficulty,
  subsidy from the halving schedule, and total fees two independent
  ways (coinbase output minus subsidy; sum of per-transaction fees).
- blockchain/service.py: MonitorService. Sync walks only new heights,
  detects reorgs by comparing stored hashes with the node while
  walking down to the fork, records chain events (new_block,
  mempool_new, reorg), tracks sync state, and never lets an RPC
  failure escape its run loop (state becomes "disconnected").
- agent/interface.py: new structured questions on top of Task 001:
  latesthash, blocks N, analyze REF, txcount, difficulty, mempool,
  tx TXID, newblock SINCE_HEIGHT, sync.

## RPC methods used

getblockchaininfo, getblockcount, getbestblockhash, getblockhash,
getblock (verbosity 1 and 2), getblockheader, getchaintips,
getrawtransaction, decoderawtransaction, getmempoolinfo,
getrawmempool, getmempoolentry, plus wallet and generation methods
inherited from Task 001 (createwallet, getnewaddress,
generatetoaddress, sendtoaddress, invalidateblock in tests).

## Test evidence (real run, 2026-11-13)

- Chain prepared to height 130; service synced all 131 blocks
  (genesis to tip) in one pass.
- Wallet spend of 0.5 BTC: seen in mempool, fee computed at 2820
  sats (vsize 141), and the mempool entry fee agreed exactly.
- After generating one block: the transaction confirmed once, and
  the block analysis verified merkle root True, PoW True, fee
  agreement True (coinbase accounting equals per-transaction sum).
- Fabricated txid: TxUnavailable raised with the node reason.
- decoderawtransaction round trip matched the txid.
- Store closed and reopened: blocks, tip and transaction all intact.
- Reorg: invalidateblock at tip minus 2, then 5 new blocks. The
  service detected the fork, dropped 3 stored blocks, recorded the
  reorg event, and ended with the store tip equal to the node tip.
- Dead port client: sync reported "disconnected", run loop completed
  its cycles without raising.

## Known limitations

- Fees for a transaction require fetching every input's previous
  output. With txindex on (our node) this works for chain
  transactions; without it, fee_sats is None and fee_note says why.
- Mempool tracking is snapshot based per sync cycle; a transaction
  that enters and leaves between polls is not recorded.
- The service polls height instead of using ZeroMQ notifications.
  Polling is deliberate for this phase: fewer moving parts, and the
  RPC budget is measured (one getblockchaininfo per cycle plus one
  fetch per new block).
